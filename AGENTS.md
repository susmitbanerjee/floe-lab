# floe-lab engineering rules

## Purpose
floe-lab is Floe's test bench: storage, catalog, data with known answers, and benchmarks.
It must never become a second product. If a feature doesn't help test Floe, it doesn't belong here.

## Reproducible
- A clean checkout plus `make up && make data PROFILE=small && make check` must give the same
  results on any machine, every time.
- Data is deterministic: every value derives from a seed and row coordinates, never from wall
  clock, thread scheduling or unseeded randomness.
- Pin everything: container images by digest, Python dependencies through uv.lock, Terraform
  providers by exact version with the lock file committed, GitHub Actions by commit SHA.
- Expected answers are generated by a script that is committed, never edited by hand. Each file
  records the command, tool versions and data profile that produced it.

## Simple
- Make is the single entry point. Every task is a documented `make` target; no hidden steps.
- Smallest thing that works. No frameworks, no plugin systems, no config layers beyond
  one env file and command-line flags.
- Python for data and checks, shell only for glue under 50 lines, Terraform for AWS.
- Rule of three before extracting shared helpers.

## Python
- Python version pinned in .python-version; uv manages environments and the lock file.
- Type hints everywhere; mypy --strict passes. ruff format and ruff check pass.
- Small functions with clear names; a module per job (generate, write, check, bench).
- Fail fast with messages that say what failed and what to do. No bare except; no silent fallbacks.
- Stream large data in batches. Never hold a 100 GB profile in memory.

## Shell
- #!/usr/bin/env bash and set -euo pipefail at the top. Quote every variable.
- shellcheck passes with no disabled rules unless a comment explains why.

## Docker
- Images pinned by digest, with the human-readable tag in a comment.
- Every published port binds to 127.0.0.1 only.
- Every service has a healthcheck; `docker compose up --wait` must succeed or fail clearly.
- Lab credentials are obviously fake (e.g. floe-lab-access / floe-lab-secret), live in
  .env.example, and must never be reused anywhere else.

## AWS and Terraform
- Least privilege: Floe's role can only read. The data-writing role is separate and short-lived.
- Everything is tagged project=floe-lab, owner, and expires-on.
- Cost guardrails are code: an AWS Budget alarm, an Athena per-query scan limit, S3 lifecycle
  expiry, and auto-shutdown on any EC2 instance.
- `make aws-down` destroys everything `make aws-up` created. Never leave state behind.
- terraform fmt, terraform validate and tflint pass; a config scanner (trivy config) passes.

## Secrets
- No real secret in the repo, ever. AWS access comes from the caller's own profile or SSO session.
- gitleaks runs in CI and as a pre-commit hook.
- Never print credentials, session tokens or presigned URLs in logs or results files.

## Testing
- pytest for the generator and checks. Hermetic unit tests run without Docker or network.
- Integration tests that need the stack are marked @pytest.mark.stack and run in CI with Compose.
- The generator has a golden test: a tiny profile's output hashes must match committed hashes.

## Working loop
- Small PRs, conventional commits, DCO sign-off (git commit -s).
- Before saying done, run `make lint test` and paste the output; list anything not done.
- Check tool and library behaviour against the pinned version's docs. Never invent flags or APIs.
  If reality differs from the prompt, stop and write docs/adr/NNNN-title.md.
